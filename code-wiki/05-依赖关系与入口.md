# 依赖关系与入口

## 1. Python 包依赖

项目通过 `pyproject.toml` 管理依赖。

### 1.1 核心依赖

- `numpy`
- `scipy`
- `scikit-learn`
- `matplotlib`
- `omegaconf`

这些依赖支撑了：

- 数值矩阵运算
- 稀疏矩阵表示
- 聚类与部分近似算法
- 实验绘图
- YAML 配置读取与覆盖

### 1.2 开发依赖

- `pytest`
- `ruff`

### 1.3 可选依赖

#### `experiments`

- `tensorly`
- `ogb`

适用于：

- 张量基线
- OGB 数据集相关实验

#### `ann`

- `faiss-cpu`
- `hnswlib`

适用于：

- Q2 external ANN 路径
- 更接近工业 ANN 后端的实验比较

## 2. HPC 环境依赖

`requirements-hpc.txt` 是面向 HPC/AutoDL 环境的冻结依赖集合。

特点：

- 版本更明确
- 包含 `torch`, `ogb`, `pandas`, `tqdm` 等实验环境常用包
- 安装流程通常是：
  - `pip install -r requirements-hpc.txt`
  - `pip install -e .`

## 3. 内部代码依赖关系

## 3.1 包级别关系

```text
compression
  -> factorized store 与压缩器实现

index
  -> 各类可独立复用的索引结构

query_engine
  -> 依赖 compression 和 index

evaluation
  -> 依赖 compression，部分逻辑依赖 query_engine

scripts
  -> 依赖上述所有核心模块
```

## 3.2 实际开发时的依赖优先级

如果要理解一个功能通常会落在哪层，可以按下面判断：

- 修改压缩算法或残差门控：看 `compression/`
- 修改查询结果或路径选择：看 `query_engine/`
- 修改索引结构或索引存储：看 `index/`
- 修改实验逻辑和结果输出：看 `scripts/` + `evaluation/`
- 修改数据生成和真实数据预处理：看 `data_loader/`

## 4. 包入口

### 4.1 顶层包入口

`src/spectralstore/__init__.py` 对外导出了一小组核心符号：

- `FactorizedTemporalStore`
- `TemporalCOOResidualStore`
- `QueryEngine`
- `BoundedQueryResult`
- `ExactMIPSIndex`
- `RandomProjectionANNMIPSIndex`
- `TopNeighborQueryPlan`

这说明项目对外暴露的核心 API 重心在：

- 存储表示
- 查询引擎
- Q2 基本索引

### 4.2 子包入口

- `compression/__init__.py`
  - 暴露压缩器、配置、注册表和 store
- `query_engine/__init__.py`
  - 暴露 `QueryEngine`、`QueryIndexManager`、`Q2PathPlanner`
- `index/__init__.py`
  - 暴露所有索引类型
- `data_loader/__init__.py`
  - 暴露真实和合成数据加载接口
- `evaluation/__init__.py`
  - 暴露指标、实验工具和报表函数

## 5. 运行入口

项目没有在 `pyproject.toml` 中注册 `console_scripts`，因此实际运行入口不是命令行安装后的全局命令，而是直接执行脚本文件。

### 5.1 数据入口

- `scripts/data/download_dataset.py`

作用：

- 下载 `bitcoin_otc`
- 下载 `bitcoin_alpha`

### 5.2 实验入口

主要入口按实验分组：

- `scripts/exp1/*.py`
- `scripts/exp2/*.py`
- `scripts/exp3/*.py`
- `scripts/exp4/*.py`
- `scripts/exp4_v2/*.py`
- `scripts/exp5/*.py`

其中最典型的系统级入口包括：

- `scripts/exp3/run_query_benchmark.py`
- `scripts/exp3/run_query_index_scaling.py`
- `scripts/exp4_v2/run_residual_query_robustness.py`
- `scripts/exp5/run_ard_diagnostic.py`

### 5.3 HPC 批跑入口

- `scripts/hpc/run_system_direction.sh`
- `scripts/hpc/run_advisor_batch_abc.sh`
- `scripts/hpc/run_external_ann_batch.sh`

其中 `run_system_direction.sh` 会依次执行：

- Exp3 query benchmark
- Exp4_v2 residual-query robustness
- Exp5 ARD diagnostic

## 6. 配置入口

实验脚本的真正“参数入口”通常不是命令行本身，而是 YAML 配置文件：

- `experiments/configs/exp1/*.yaml`
- `experiments/configs/exp2/*.yaml`
- `experiments/configs/exp3/*.yaml`
- `experiments/configs/exp4/*.yaml`
- `experiments/configs/exp4_v2/*.yaml`
- `experiments/configs/exp5/*.yaml`

脚本一般通过以下方式接收配置：

```bash
python scripts/exp3/run_query_benchmark.py --config experiments/configs/exp3/query_benchmark.yaml
```

并支持：

```bash
python scripts/exp3/run_query_benchmark.py --config ... --set workload.num_q1=100
```

## 7. 结果产物入口

实验运行完成后，主要产物通常在输出目录下生成：

- `query_records.csv`
- `summary.csv`
- `metrics.json`
- `summary.md`
- `resolved_config.yaml`
- `run_metadata.json`

对理解系统很重要的一点是：

- 代码入口在 `scripts/`
- 参数入口在 `experiments/configs/`
- 结果入口在 `experiments/results/` 或用户指定目录

## 8. 开发时最常用入口清单

### 8.1 作为库使用

适合在 notebook、测试或临时脚本中：

```python
from spectralstore.compression import create_compressor, spectral_config_from_mapping
from spectralstore.query_engine import QueryEngine
```

### 8.2 作为实验框架使用

适合复现实验：

```bash
python scripts/exp3/run_query_benchmark.py --config experiments/configs/exp3/query_benchmark.yaml
```

### 8.3 作为批处理系统使用

适合 AutoDL/HPC：

```bash
bash scripts/hpc/run_system_direction.sh
```

## 9. 入口选择建议

- 想验证单个类或函数：直接导入 `src/spectralstore/`
- 想跑单个实验：执行 `scripts/exp*/...`
- 想大规模批跑：执行 `scripts/hpc/...`
- 想修改方法配置：改 `experiments/configs/...`
- 想追踪结果来源：查 `run_metadata.json` 与 `resolved_config.yaml`

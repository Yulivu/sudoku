# 运行与实验手册

## 1. 本地安装

推荐在仓库根目录执行：

```powershell
python -m pip install -e ".[dev]"
python -c "import spectralstore; print('spectralstore import ok')"
```

如果需要实验相关依赖，可安装：

```powershell
python -m pip install -e ".[dev,experiments]"
```

如果需要 ANN 相关依赖，可安装：

```powershell
python -m pip install -e ".[dev,ann]"
```

注意：

- `faiss-cpu` 在 Windows 上可能受限，项目当前也明确区分了本地 fallback 与真实外部 ANN 证据。
- 本地开发更适合跑小规模 smoke 或 medium 规模实验。

## 2. 数据准备

下载真实数据集：

```powershell
python scripts/data/download_dataset.py bitcoin_otc
python scripts/data/download_dataset.py bitcoin_alpha
```

下载后文件默认放在：

- `data/raw/soc-sign-bitcoinotc.csv.gz`
- `data/raw/soc-sign-bitcoinalpha.csv.gz`

如果是合成实验，则无需额外下载，脚本会直接通过 `data_loader/synthetic.py` 生成数据。

## 3. 最小运行闭环

建议先验证一个完整但成本较低的链路：

```powershell
python scripts/exp3/run_query_benchmark.py --config experiments/configs/exp3/query_benchmark.yaml --set workload.num_q1=20 --set workload.num_q2=20 --set workload.num_q3=5 --set workload.num_q4=10
```

这样可以一次性验证：

- 配置加载
- 数据生成/加载
- 压缩器构建
- `QueryEngine` 执行
- 指标统计
- 输出目录写入

## 5. 配置系统用法

实验脚本统一使用：

- `--config <yaml>`
- `--set key=value`

例如：

```powershell
python scripts/exp1/run_exp1_theory_validation.py --config experiments/configs/exp1/theory_validation.yaml --set num_repeats=1
```

配置读取由 `evaluation/experiment.py` 中的 `load_experiment_config()` 完成，具有以下特点：

- 支持 OmegaConf dotlist 覆盖
- 会校验覆盖键是否合法
- 输出 resolved 配置用于复现

## 6. 输出目录与产物

典型输出包括：

- `metrics.json`
- `summary.md`
- `resolved_config.yaml`
- `run_metadata.json`

部分实验还会额外输出：

- `query_records.csv`
- `summary.csv`
- `paper_table.md`
- 各类 plot 图片
- Q2/Q3/Q4 的索引或 benchmark 汇总表

### 6.1 `run_metadata.json` 的价值

它会记录：

- 实际命令
- 当前工作目录
- 配置路径和 hash
- Python/平台信息
- 关键包版本
- git branch / commit / dirty 状态

因此它是定位“这组结果到底怎么跑出来的”的首要依据。

## 7. HPC / AutoDL 运行方式

### 7.1 环境安装

在 Linux/HPC 环境中通常先执行：

```bash
pip install -r requirements-hpc.txt
pip install -e .
python -c "import spectralstore; print('spectralstore ok')"
```

### 7.2 系统方向批跑

```bash
bash scripts/hpc/run_system_direction.sh
```

它会顺序执行：

- Exp3 query benchmark
- Exp4_v2 residual-query robustness
- Exp5 ARD diagnostic

### 7.3 顾问反馈批次

```bash
DRY_RUN=1 bash scripts/hpc/run_advisor_batch_abc.sh
bash scripts/hpc/run_advisor_batch_abc.sh
```

### 7.4 外部 ANN 批次

安装真实后端后再执行：

```bash
python -m pip install faiss-cpu
python scripts/hpc/preflight_external_ann.py --backend faiss_ivfpq
DRY_RUN=1 EXTERNAL_ANN_BACKEND=faiss_ivfpq bash scripts/hpc/run_external_ann_batch.sh
EXTERNAL_ANN_BACKEND=faiss_ivfpq bash scripts/hpc/run_external_ann_batch.sh
```

说明：

- `numpy` backend 只是本地 smoke/debug fallback
- 正式 external ANN 证据应尽量使用 `faiss_ivfpq` 或 `hnswlib_ip`

## 9. 阅读和调试建议

如果想从运行结果回溯代码，推荐路径如下：

1. 从某个 `scripts/exp*/run_*.py` 开始。
2. 找 `load_experiment_config()` 和 `load_dataset()`。
3. 看 `create_compressor()` 和 `fit_transform()`。
4. 看 `QueryEngine.from_config()`。
5. 看具体 workload 如何调用 Q1-Q5。
6. 最后看 `write_metrics()` / `write_summary()` / `write_experiment_outputs()`。

如果想从代码理解运行方式，推荐反过来：

1. 先读 `FactorizedTemporalStore`
2. 再读 `QueryEngine`
3. 再读 `run_query_benchmark.py`

## 10. 已知限制

- 项目当前以研究工程为主，不提供生产级服务接口。
- 部分 ANN/PQ/IVFPQ 路径属于 prototype 或实验路径，不应默认视为工业级实现。
- Windows 本地环境更适合小规模验证，不一定适合完整 HPC 级实验。
- 外部 ANN 的正式证据需要明确区分 fallback 与真实后端。

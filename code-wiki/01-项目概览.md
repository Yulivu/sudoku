# 项目概览

## 1. 项目定位

`SpectralStore` 是一个研究型时序图 AQP 系统，核心目标不是单纯做图压缩，而是把压缩表示当作一种“物理存储设计”，支持以下能力：

- 将时序图快照压缩为低秩因子化表示。
- 在压缩域上直接执行查询。
- 用稀疏残差层补充事件、异常与观测语义。
- 通过索引结构加速常见查询，尤其是 Q2/Q3/Q4。
- 在实验中统一评估存储、精度和延迟的权衡。

项目当前主叙事更接近“预算感知的时序图 AQP 存储与查询系统”，而不是“某个压缩算法全局优于所有 SVD 基线”。

## 2. 核心查询模型

系统围绕 5 类查询组织实现：

| 查询 | 含义 | 核心实现位置 |
| --- | --- | --- |
| `LINK_PROB(u, v, t)` | 查询时刻 `t` 上边 `(u, v)` 的得分/概率估计 | `query_engine/engine.py` |
| `TOP_NEIGHBOR(u, t, k)` | 查询节点 `u` 在时刻 `t` 的 top-k 邻居 | `query_engine/engine.py` |
| `COMMUNITY(t)` | 查询时刻 `t` 的社区划分 | `query_engine/engine.py` + `index/community.py` |
| `TEMPORAL_TREND(u, v, t1, t2)` | 查询边 `(u, v)` 在时间区间上的趋势 | `query_engine/engine.py` + `index/temporal.py` |
| `ANOMALY_DETECT(t, threshold)` | 利用残差检测异常边/事件 | `query_engine/engine.py` |

## 3. 仓库组成

```text
data/                  数据目录
docs/                  项目手册、交接与扩展说明
experiments/configs/   各实验 YAML 配置
scripts/               CLI 风格入口脚本
src/spectralstore/     核心实现
```

其中 `src/spectralstore/` 下的子包职责如下：

- `compression/`: 压缩器、存储表示、残差格式、压缩器注册表。
- `query_engine/`: Q1-Q5 查询执行、路径规划、索引接入与缓存。
- `index/`: Exact/ANN/PQ/IVFPQ/Q3/Q4 等索引结构。
- `data_loader/`: 真实数据集与合成数据集加载/生成。
- `evaluation/`: 配置读取、指标计算、结果落盘、实验元数据。
- `baselines/`: 基线相关实现。

## 4. 技术栈

- 语言: Python 3.10+
- 数值计算: `numpy`, `scipy`
- 机器学习/聚类: `scikit-learn`
- 配置系统: `omegaconf`
- 绘图: `matplotlib`
- 可选实验依赖: `tensorly`, `ogb`
- 可选 ANN 依赖: `faiss-cpu`, `hnswlib`

## 5. 设计特点

### 5.1 库与脚本分离

- 核心逻辑放在 `src/spectralstore/`。
- `scripts/` 只负责解析参数、加载配置、调用核心库并写出结果。
- 这种设计让实验代码可复用、可测试、可导入。

### 5.2 因子层 + 残差层

系统使用两层表示：

- 因子层: `left / right / temporal / lambdas`
- 残差层: 稀疏残差，支持 `csr tuple` 或 `TemporalCOOResidualStore`

这意味着查询可按语义选择：

- 只看背景结构时，走 factor-only 路径。
- 关注观测事件时，走 factor + residual 路径。
- 关注异常事件时，直接依赖 residual 层。

### 5.3 查询与索引耦合

Q2/Q3/Q4 都有明确的索引扩展：

- Q2: exact、materialized、ANN、PQ、IVFPQ、external ANN
- Q3: 社区倒排索引
- Q4: B+ tree 风格时间趋势索引

### 5.4 实验可复现性优先

实验脚本通过统一约定输出：

- `metrics.json`
- `summary.md`
- `resolved_config.yaml`
- `run_metadata.json`

其中 `run_metadata.json` 会记录命令、环境、包版本和 git 状态，便于追踪结果来源。

## 6. 使用者心智模型

理解该仓库最有效的方式是把它看成 4 层：

1. 数据层: 真实或合成时序图快照。
2. 压缩存储层: 用压缩器生成 `FactorizedTemporalStore`。
3. 查询/索引层: 用 `QueryEngine` 与索引结构执行 Q1-Q5。
4. 实验层: 用 `scripts/` + YAML 配置批量运行并产出论文/系统评估证据。
